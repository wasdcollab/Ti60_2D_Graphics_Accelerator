# 冲击波环 / 命中核心改到扫描线 + hitstop（2026-10-25）

方案里的第 3 项：**命中表演**。三件事，其中两件在硬件、一件在固件：

1. **程序化冲击波环**（新扫描线图层 `video_fx_ring`）：环/光盘从像素坐标算，不再用 BitBlt 画。
2. **加法核心**（同一个图层的 `add` 路径）：命中瞬间的高亮盘，饱和相加，真的会过曝到白。
3. **hitstop**（纯固件）：重击命中时世界冻结 2~3 帧，画面照常渲染。

## 为什么值得改

改之前，一次命中在帧缓冲里是这样画出来的：

| 旧路径 | 代价 |
|---|---|
| `burst_render()`：24 帧预烘焙 112×112，每帧一次 `OP_ALPHA` blit | 每帧约 3 千个 beat × 3 次 DDR 传输（读 src + 读 dst + 写 dst）≈ 9.4k 总线周期，外加下一帧 `damage_restore` 再把同一块底板读回写回 ≈ 6k 周期 |
| 自机中弹环：16 个 2×2 `r_fill` | **16 条 BitBlt 命令**（每条都要等引擎空闲），16 个脏矩形 |
| 素材 | 1.26 MB 的 24 帧环常驻 DDR |

改之后：

| 新路径 | 代价 |
|---|---|
| 四个 96-bit 描述符 | 每帧 **12 次 APB 写**（约 48 个 core 周期） |
| 环/核心 | 0 DDR 读、0 DDR 写、0 条 BitBlt 命令、0 个脏矩形 |
| 连续性 | 半径连续增长，不再受 24 帧量化 |

## 硬件

新文件 `rtl/display_engine/2_layer_generators/video_fx_ring.v`，四个槽位，每个槽位是一个圆环
（`r_in = 0` 时是实心盘）：

```
covered = r_in^2 <= (x-cx)^2 + (y-cy)^2 <= r_out^2
```

* 内外边缘各 2 px 羽化，羽化用 `(r±2)^2 = r^2 ± 4r + 4` 展开，**不额外占乘法器**；
* 槽位 0 优先级最高，合成器只混一次（不是四个环叠加），所以这一层只花一次 128-bit 混合；
* 两级流水：A 级算 `dx^2+dy^2`（每槽两个 13×13 有符号乘），B 级做比较、羽化、优先级选择并寄存。
  **两级正好等于合成器自身从 `cur_pixel` 到 stage-2 的延迟**，所以环像素和它要混的那层背景同拍到达，
  不需要延迟线、也不会把画面平移；
* DE 与遮挡盒（`mask_x[31]`）跟着几何一起延迟一级，否则每段像素的最后一个会被裁掉；
* 资源：**DSP +16**（每槽 2 个算距离 + 2 个算 `r^2`），**BRAM 0**，寄存器约 700 个。

合成器 `video_pixel_compositor.v` 新增一个 **stage 2b**：环在激光之上、自机光束之下混合。
单独一级是为了不让 stage 2/3 的组合路径变长（像素域原来只剩 1.7 ns 余量）。

APB 在 **bank 2**（bank 0 已经用满）：

| 偏移 | 内容 |
|---|---|
| `0x200 + 16*slot + 0` | `{en[31], add[30], r_out[29:21], cy[20:11], cx[10:0]}` |
| `0x200 + 16*slot + 4` | `{15'd0, r_in[24:16], alpha[7:0]}` |
| `0x200 + 16*slot + 8` | `{8'd0, rgb[23:0]}` |

`add=1` 走饱和相加（忽略 alpha，亮度由颜色本身携带），`add=0` 走 alpha 混合。
参数在 `v_cnt == V_ACT && h_cnt == 0` 这一拍整体锁存，和 weather/laser/beam 完全一样的帧原子语义。

## 固件

* `fx_rings_upload()`（`sw/app/main.c`）：把 `visual_fx` 池里最新的命中打包成四个槽位。
  - 槽 0 留给**自机中弹环**（`hit_ring_timer`），因为它是优先级最高的那个；
  - `visual_fx` 的年龄 0..3 = 加法核心（白→灰四档淡出），4..23 = 展开的混合环（白→琥珀）；
  - 12 次 APB 写每帧无条件执行，顺便清掉刚过期的槽位。
* 旧的 `burst_render()` 和 16 点填充环都留在 `#if FX_RINGS` 的 `#else` 分支里，可以一键回退对比。
* **hitstop**：`take_hit()` 置 2 帧，BOSS 击破置 3 帧；主循环在 `hitstop` 非零时把
  `max_steps` 置 0（逻辑不推进）并丢弃欠账（不补帧），渲染照常。

## 上板验收

1. 进 BOSS STAGE，按住攻击打 BOSS，看命中处：应该出现**白色核心 + 一圈连续膨胀的环**，
   而不是原来的 24 帧台阶；自机中弹时环更大更亮。
2. 命中瞬间画面应**停 2 帧**（hitstop），然后继续。若觉得停得太长/太短，改
   `HITSTOP_HIT` / `HITSTOP_KILL`（0 关闭）。
3. FPS 应该不降反升：原来每帧几十条 BitBlt 命令和 1.26 MB 的环素材读，现在只剩 12 次 APB 写。
   若 FPS 反而降了，先查串口 `T`（分桶任务周期）和 `n`（BitBlt 命令数）——`n` 应该明显变小。
4. 想做 A/B：把 `sw/app/main.c` 的 `#define FX_RINGS 1` 改成 0，重新 `python sw/build_firmware.py`，
   旧路径会原样回来（素材、代码都还在）。

## 已知限制

* 只有 4 个槽位。固件按“自机中弹环 > 最新命中”排序取前 4，第 5 个及以后当帧不显示——
  连续高速命中时会看到部分环被吃掉，这是刻意的取舍（每加一个槽位就多 2 个 DSP 和一整套比较器）。
* 加法路径忽略 alpha，所以加法环的淡化必须靠颜色变暗（固件里用 `core_fade` 表做）。
* 环是扫描线层，画在帧缓冲内容之上：击中时如果正好有对话框/标题卡在帧缓冲里，环会盖在它上面。
  面板会声明 weather 遮挡盒，但标题卡不声明，所以这一点目前没处理。
* 本次没有把 `MM_BURST_FRAME` 的 1.26 MB 素材从 DDR 布局里删掉（回退路径还要用）。
