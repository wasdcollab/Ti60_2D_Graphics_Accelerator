## 基线与范围

用户反馈上一轮配比候选在 LOAD 2112 下：**SPRITES 2116、FPS 37、DROP 0，画面和音乐正常**。
对应候选归档为 `backups/boss_spread_round2_20261015_151548/`，固件 SHA-256：
`fbdacf345d0f420714947e563d68e778e4ccd4b9e3e720a0ec49b58675749b43`。

本次保持弹型配比、补弹预算、速度、弹池容量、游戏规则、透明覆盖 RTL、音乐和时钟约束不变。
只优化 `sw/app/main.c` 三处 CPU 热路径。没有通过降低弹数或降低逻辑更新频率换取显示帧率。

## 代码改动

1. `bucket_put_run`：一次生成完整桶项，跨组时直接递增打包后的 tile-row 字段；深度指针与终止指针比较，省去重复钳位、移位、OR 和索引恢复。
2. `alloc_bullet_range`：改为指针遍历，仍严格选范围内最低空槽。没有引入循环分配游标，不改变槽位优先级和 orb 预留池。
3. `aim_index` / `bucket_build`：水平向量走等价快速分支，精简象限映射；普通飞行米弹第一次渲染时缓存朝向，之后读取缓存。

### 桶项数学边界

对任何与 tile 的占用行区间相交的桶组，偏置后的 tile row 为 `g*8-row+8`，
它位于 `[r0+1, r1+7]`。当前图块满足 `0 <= r0 < r1 <= 26`，故范围为 `[1,33]`。
上下屏幕裁剪只会缩小相交集合，不改变该界限。因此原先的 0..63 钳位不会起作用；
按 `8<<11` 递增六位字段也不会向相邻 slot 字段进位。

### 朝向缓存约定

- 敌弹 `color[2:0]` 仍为 hue，`color[6:3]` 存方向，bit 7 为有效位。
- 所有普通出生函数以原始 hue 重写 color，自然使复用槽位的旧缓存失效。
- held/零速度弹每帧跟踪玩家，不填缓存；held 发射后首次进入普通飞行路径才建立缓存。
- 改变速度的 lance 分支和 orb 分支在缓存路径之前返回，不使用该缓存。
- 当前代码中普通飞行米弹没有中途改变速度的路径。**未来新增这种机制时，必须同时清除 color bit 7，或重算缓存。**
- 调试器直接修改速度也必须遵守失效约定；颜色统计和颜色比较应使用 `color & 7`。

这次是延迟到首个渲染帧建立缓存，没有采用上一轮因空间不足放弃的逐出生点缓存实现。

## 等价性定向测试

`tools/test_fps_kernels.py` 直接运行真实链接固件的叶函数，以独立公式核对输出：

- 16397 个桶编码用例：19 个 tile，逐行覆盖屏幕及上下边界，极端 int16 坐标，深度 0/127/128，逐项核对写地址、完整 32 位数据、账本、DROP 和有效范围。
- 2786 个分配用例：玩家池和普通敌弹池的每一个最低空槽、满池；预留 orb 尾部为空时普通分配仍不能侵占。
- 69792 组朝向：全部有符号 8 位 vx/vy 组合，另加屏幕尺度的瞄准向量采样；与原始整数公式一致。

| 相同输入的 VM 指令总数 | 基线 | 最终候选 |

| 桶编码 | 1803237 | 1488907 |
| 分配器（含外层边界维护） | 21789666 | 13613082 |

桶编码约减少 17.4%，分配器约减少 37.5%。均匀向量下朝向函数本身反而增加约 4.8%，
不能把该项单独宣传为普遍提速；实际场景包含大量水平弹，并且方向缓存减少了反复调用。
最终是否有效以自然帧剖析及上板 FPS 为准。
