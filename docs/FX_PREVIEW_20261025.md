# 特效 A/B 预览（2026-10-25）

同一帧、同一机位，只改后期，回答"按建议做，视觉效果会不会提一档"。

## 产出

`work_sim/fx/` 下，两套场景各四张：

| 文件 | 内容 | 说明 |
|---|---|---|
| `1_original[_boss].png` | 原始 | VM 直出：真实固件 + 真实扫描线模型，**没有任何后期**（等价 GLOW FX = OFF） |
| `2_current_glow[_boss].png` | 现状发光 | 只对固件已经标记为发光的像素做泛光（弹幕/激光/粒子/刀光），≈ 板上现在开 GLOW |
| `3_added_glow[_boss].png` | **只加发光** | 在 2 的基础上，把"画面自己的高光"（月亮、冰脊、雪点、BOSS/自机高光）也当发光体 |
| `4_glow_ui[_boss].png` | **发光 + 半透明 UI** | 3 的基础上，暂停卡按 74% 不透明合成，战斗从面板后面透出来 |

`_boss` = 第一关（冰雪、月亮、白雪）平静帧，`0_sheet_boss.png` 是它的 2×2；
不带后缀 = 压力场 1228 发满屏帧，`0_sheet.png` 是它的 2×2。

场景是真的：`tools/render_fx_compare.py` 用现成固件在 VM 里跑到目标状态，
由 `simulator/scanout_model.py` 按 RTL 的图层优先级合成，包含雪、激光、弹幕、自机刀光、HUD。

## 方法与其边界

- **泛光是近似，不是 bit 精确**：`video_bloom_filter.v` 是 5 行 × ±15 抽头的卷积，预览用
  同等作用范围的可分离高斯（σv≈2、σh≈7）加 0.86 软拐点代替，位置与 RTL 一致（合成之后、色彩矩阵之前）。
  看的是"有没有那一层光"，不是逐像素复刻。
- **半透明 UI 是合成预览**：把 `docs/recovery_evidence/recovered_pause.png` 里的真实卡片区域按 74%
  叠到同一帧上。真做的时候是固件把面板改用 `r_alpha` 画，卡片本身不变。
- 场景帧本身没有任何改动，`1_original` 就是当前代码的真实画面。

## 量化

| 场景 | 3 相对 1：平均 \|Δ\| | 变化 >8 的像素 | 2 相对 1（现状发光） |
|---|---|---|---|
| 平静帧（第一关） | 3.11 / 255 | 7.0% | 2.49 / 255 |
| 满屏帧（1228 发） | 4.80 / 255 | 13.4% | 3.40 / 255 |

## 结论

**满屏帧**：三张几乎一样。弹幕本身已经是高饱和发光体，泛光只是给已经很亮的画面再加一层空气感——
**这一项在弹幕满屏时不是"提一档"，是"提一点"**。

**平静帧**：差别一眼可见。月亮有了光晕、冰脊变成一条发光的带、雪点成为闪烁的亮点，
画面的"光源"从无到有。**这一项在中低密度和过场/标题/对话时最值钱**。

**半透明 UI**：两张里都是最稳的一项，战斗从面板后透出来，观感直接从"贴了块灰板"变成"有景深"。

因此建议：**发光（P0-1）和半透明 UI（P0-3）值得做，但别指望它把满屏弹幕战变成另一个游戏**；
真正的"提一档"要靠 ② 命中表演（hitstop + 三层冲击 + 程序化环）和 UI 包装。
如果目标是答辩观感，性价比最高的是"发光 + 半透明 UI + hitstop"这三件，
加起来不到一天，且不需要碰已经 100% 的 BRAM。

## 复现

```powershell
python tools/render_fx_compare.py --mode boss --frames 260 --tag boss
python tools/render_fx_compare.py --mode pressure --load 1200 --frames 40
```

两次运行都会把抓到的帧缓存成 `work_sim/fx/capture*.npz`；之后调 `--gain` / `--sigma-h`
只是几十秒的重算，不用再跑 VM。加 `--recapture` 重新抓帧。
