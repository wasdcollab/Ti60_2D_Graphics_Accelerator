# 8000 档攻击提速与普通关卡特效交接

日期：2026-10-21。硬件：Ti60F225，core 100 MHz，HDMI 约 75 Hz。

## 验收边界

- 用户已确认旧版 LOAD 8000 不攻击帧率稳定、DROP=0；攻击后下降，降低到约 6000 才恢复。
- 本次实现的是新候选，尚未获得新版本上板反馈。仿真指令数不是板上 FPS，不能据此宣布长期 60/75 FPS 达标。
- 未自动下载 JTAG，未擦写配置或音乐 Flash。现有音乐、接口和时钟配置保留。
- 工作区原本有大量队友改动，本次未回退这些改动；修改前备份在 `backups/boss_attack_20261021_baseline/`。

## 根因与实现

1. 固件原来仅启动硬件分桶，未打开已有的运动功能。8000 发敌弹仍由 CPU 逐颗更新、裁剪和碰撞检测，攻击时叠加玩家弹、命中特效和背景恢复，容易错过 VSync。
2. 压力场普通敌弹的运动和出屏回收现交给 DMA 协处理器，随分桶一次完成。CPU 保留玩家弹、反弹长矛和 32 槽特殊弹保留区的更新。普通关卡仍走原 CPU 碰撞路径。
3. 每个逻辑 tick 才提交一次运动任务。无逻辑更新的重绘、暂停重绘不移动弹幕。启动前清理缓存，完成后再读取 DMA 写回；去掉帧尾第二次无界等待和无条件消费旧计数。
4. 碰撞候选范围从 129x129 收紧到实际擦弹范围 31x31。候选 FIFO 满 512 项时回退到前段弹幕池检查，不能静默漏判。空任务正确写回零存活数。
5. 修正协处理器在运动模式下漏计保留区弹幕的问题，包含保留区长矛的边界情况。Python/C++ 模型同步边界、保留区不重复运动及候选上限；C++ 原生扩展本机没有重新编译，回归使用 PyPy 纯 Python 模型。
6. 长矛改为 DDR 存活索引列表，更新和绘制都不再扫描首尾长矛之间的数千个普通槽位。处理槽位复用去重，更新时压紧索引，不修改长矛反弹规则。
7. 补弹预算 48 -> 96；LOAD >= 4000 时增加 64 发真实弹幕余量，覆盖帧末 DMA 出屏回收。SPRITES 仍为真实统计，不封顶、不伪造 DROP，不删除碰撞或弹幕类型来提速。

## 普通关卡与特效

- 普通关卡同时存在的小兵上限由 5/6/7 提高到 9/10/11；基础生成间隔由 60/56/52 tick 改为 36/32/28 tick。
- 三关均能生成四种小兵：瞄准三向弹、交替速度扇形弹、交替角度环形弹、大玉配两侧瞄准弹。压力场小兵上限仍为 7。
- 命中特效使用预烘焙直通 Alpha 渐隐，保留 RGB 亮度，不重复预乘。透明色键孔洞不参与混合。
- 112x112 的整块特效拷贝改为按年龄裁剪有效范围，并使用硬件 Alpha 混合。初期只处理 32x32 区域；保留弹幕实体的不透明轮廓，避免特效遮住可躲避间隙。
- 新增状态区：粒子状态 `0x048C1300..0x048C1480`；长矛索引 `0x048C1600..0x048C5600`。DDR 布局检查覆盖两者。完整保留片内 1 KiB 栈。

## 回归证据

- `tools/sim_bucket_accel.ps1 -Large -Direct` 及 `-Large`：通过，含真实 AXI Mux、独立 AW/W 随机停顿、慢 B 响应、8192 条记录、奇数边界、清尾、错误响应和运动回写逐记录比对。
- `tests/tb_alpha_fade.sv`：8192 像素通过，覆盖 Alpha 0..255、全局 Alpha 255/70、色键孔洞及流水线反压。
- `tools/test_attack_effects.py`：检查全部 24 帧实际缓存像素均落在裁剪区域内；CPU 保留区和 DMA 普通弹各移动一次；无更新重绘冻结；第 513 个碰撞候选不漏判；零存活任务清零。
- 普通关卡测试检查 450 个发布帧的敌人数量、四种小兵及大玉；原生二进制在 RV32 VM 执行，不是手写游戏替身。
- `tools/test_boss_sustained.py --load 8000 --frames 2400`：逐帧检查真实弹幕池与存活计数一致、长矛索引无重复且不遗漏，覆盖 17 种非召唤 Boss 弹幕。最终统计见下方待完成结果。
- 指令采样：旧版攻击短窗平均 306780 条/帧；新候选短窗平均 54649 条/帧（41729..71832）。场景仍使用真实游戏和攻击；补弹节奏不同，所以不是同一帧状态的锁步对比，更不是 DDR 时序或 FPS 预测。
- 第一轮仅接通 DMA、未换长矛索引的版本在完整轮换中最低降到 7476 SPRITES，促成本次索引和补弹改进，不能把第一轮短窗结果当最终验收。

## 上板步骤

1. 使用最终候选目录中的 `.bit` 做 JTAG 临时下载，保留已有素材和音乐 Flash。
2. 先确认菜单、背景、音乐和音量正常，再进入 BOSS STAGE，切到 LOAD 8000。
3. 持续按住攻击至少 5 分钟，期间移动、切换可用武器，观察全部弹幕轮换；记录 SPRITES 最低值、FPS 最低/通常值、DROP 峰值。
4. 暂停/恢复、降低再提高 LOAD，检查弹幕没有重复移动、旧长矛残影和透明方框。
5. 进入普通三关，检查小兵密度、四种弹幕、击中/击破渐隐；确认光效不遮蔽弹幕边界。
6. 验收目标仍是 LOAD 8000 攻击长期 >=60 FPS，尽量保持 75 FPS、DROP 尽可能低。未收到本候选板测前保持“待验证”。

## 继续工作注意

- BRAM 占用高是资源容量指标，不等同于运行时 DROP 根因；本次重点是 CPU 全池扫描、DMA/CPU 责任划分及特效 DDR 工作量。
- 仿真没有板上 DDR 争用、CPU CPI、缓存 miss 延迟和真实音频并行总线流量，最终稳定性依赖上板。
- 当前 DROP 沿用既有诊断口径，包含分桶容量与预取异常相关信号；不得通过改计数口径得到“零 DROP”。
- 不要只把新固件塞进旧硬件位流：本候选包含硬件计数及碰撞候选范围修正。
