## 二、项目整体架构与软硬件协同全景

本项目是运行在**易灵思 Titanium Ti60 FPGA** 上的完整硬实时 2D 图形加速与东方风格（Touhou STG）弹幕射击游戏系统。经过架构解耦升级，系统演进为高度清晰、职责专一的 **Triad（三足鼎立）硬件架构**：

```
                    +------------------------------------------------+
                    |          Sapphire RISC-V SoC (RV32IM)          |
                    |  - 100 MHz Core Clock, 64 KB TCM (Firmware)    |
                    |  - Runs C Game Loop, Bullet Logic & Physics    |
                    +-----------------------+------------------------+
                                            | APB3 Master
                                            v
                    +------------------------------------------------+
                    |    apb_command_dispatcher (rtl/apb/)           |
                    |  - 纯命令分发中枢：APB3 从机寻址与时钟域隔离   |
                    |  - 寄存器单点写入，扇出至 BitBlt/DMA/Display   |
                    +--------+------------------+--------+-----------+
                             |                  |        |
         Pure 2D Command Bus |                  |        | Double-Buffer Base Addr
         (No Display Bloat!) v                  |        v (LEFT_NEXT / RIGHT_NEXT)
       +-----------------------+                |      +-----------------------------+
       |   bitblt_top          |                |      | dma_top (rtl/dma/)          |
       |   (rtl/bitblt/)       |                |      | - 纯数据提取引擎            |
       | - Fill / Copy / Alpha |                |      | - dma_fb_reader (双缓冲读)  |
       | - OP_ADD Saturation   |                |      | - dma_bucket_prefetch       |
       +-----------+-----------+                |      | - async_fifo (1024深/128b)  |
                   | AXI4 Read/Write            |      | - Gearbox 128b->32b (Stall) |
                   | Master (S2)                |      +--------------+--------------+
                   v                            |                     |
       +-----------------------+                |                     | AXI4 Read Master (S0)
       |   Axi_Mux (3S -> 1M)  |<---------------+---------------------+
       +-----------+-----------+                |
                   |                            | Effect & Layer Config Bus
                   v                            | (Laser, Beam, Weather, Tile, Pal)
       +-----------------------+                v
       |   video_write_guard   |              +-------------------------------------+
       | - 防欠载读写仲裁守卫  |              | display_engine_top                  |
       | - 保护读通道杜绝撕裂  |              | (rtl/display_engine/)               |
       +-----------+-----------+              | - 纯流式“艺术工坊”显示引擎          |
                   |                          | - video_timing_gen (1366x768@75Hz)  |
                   v                          | - 5 层实时过程图层发生器集群        |
       +-----------------------+              | - video_pixel_compositor (三级流水) |
       |   ddr3_top            |              | - Bloom 泛光滤镜 + 3x3 色彩矩阵     |
       | - 16-bit DDR3-800     |              +------------------+------------------+
       | - 256 MB Framebuffer  |                                 |
       +-----------------------+                                 v
                                                       +--------------------+
                                                       | dvi_encoder & TMDS |
                                                       | (85.71M -> HDMI)   |
                                                       +--------------------+
```

### 架构设计核心思想（Triad 架构与零带宽实时合成）：
1. **显存写入端（BitBLT 引擎，`rtl/bitblt/`）**：纯粹专职处理静态背景擦除、自机/敌机精灵绘制、UI 半透明遮罩混合以及大招高光饱和加法，避免 CPU 逐像素操作内存。
2. **纯数据提取端（DMA 引擎，`rtl/dma/`）**：纯粹专注显存突发吞吐与跨时钟域 FIFO 缓冲，内嵌 `video_write_guard` 守卫与 Gearbox `word_stall` 欠载相位冻结，告别一切着色与图层计算。
3. **纯流式视频显示端（Display Engine，`rtl/display_engine/`）**：针对 192 颗以上的高密度弹幕、全屏大激光、警告线、全屏下雪粒子等极高 DRAM 破坏性的图层，**彻底绕过 DDR3 Framebuffer(帧缓冲) 绘制**，在视频读出送显的几十纳秒流水线内硬件现算并叠加，省去每秒数吉字节的背景修补与反复读写开销。
4. **命令分发中枢（APB 引擎，`rtl/apb/`）**：实现控制平面与数据平面的绝对解耦，纯粹专注 APB3 协议解析与参数扇出，避免跨模块飞线纠缠。
5. **后处理流水线（Bloom + DSP 调色）**：利用 Ti60 空闲的 SRL8 移位寄存器与 DSP 乘法单元，直接对视频流施加各向同性辉光与全屏滤镜，实现 0 CPU 负担、0 DDR 流量的工业级电影光效。

### 2. `rtl/` 硬件源码目录（核心硬件实现）

#### (1) 顶层与通用基础模块 (`rtl/` & `rtl/common/`)
* **核心模块（单独剖析）**：
  * [rtl/ti60_top.v](file:///E:/FPGA/Ti60_2D_Graphics_Accelerator/rtl/ti60_top.v)：**FPGA顶层模块**。
    - **职责**：例化 PLL 锁相环时钟输入、系统复位计数逻辑、DDR3 存储器控制器顶层（`ddr3_top`）、Sapphire RISC-V SoC 软核（`soc`）、AXI4 总线调度器（`Axi_Mux`）、APB 命令分发中枢（`apb_command_dispatcher`）、2D 硬件图形加速器（`bitblt_top`）、纯数据提取引擎（`dma_top`）、纯流式视频显示引擎（`display_engine_top`）、防撕裂画面守卫（`video_write_guard`）、DVI 差分编码发送器（`dvi_encoder`）以及 I2C 手柄控制器（`i2c_gamepad_top`）。统一调度跨时钟域信号与总线绑定。
  * [rtl/common/Axi_Mux.v](file:///E:/FPGA/Ti60_2D_Graphics_Accelerator/rtl/common/Axi_Mux.v)：**AXI4 总线调度器（3 Slave -> 1 Master）**。
    - **职责**：将 CPU（S0）、Video DMA 读通道（S1）、BitBLT 读写通道（S2）汇聚并仲裁至底层的单个 128 位 DDR3 控制器接口。内部包含 AR/AW 通道轮询切换、读数据路由 ID 跟踪与写响应解耦。
  * [rtl/common/Axi_Mux_Param.vh](file:///E:/FPGA/Ti60_2D_Graphics_Accelerator/rtl/common/Axi_Mux_Param.vh)：AXI 总线调度器参数头文件。定义通道宏定义、数据位宽（128-bit）、地址位宽（28-bit/32-bit）、Burst 长度限制及优先级策略。
  * [rtl/common/i2c_gamepad_top.v](file:///E:/FPGA/Ti60_2D_Graphics_Accelerator/rtl/common/i2c_gamepad_top.v)：**I2C 手柄轮询与消抖控制器**。
    - **职责**：独立在硬件中以 100 kHz 周期自动通过 I2C 轮询外接手柄芯片（如 PCF8574/专用手柄芯片）的按键寄存器，集成硬件去抖动逻辑，并将 16 种按键动作（上/下/左/右/A/B/X/Y/Start/Select）解包为状态寄存器映射到 APB/GPIO，CPU 无需软件模拟 I2C 时序。
  * [rtl/common/simple_dual_port_ram.v](file:///E:/FPGA/Ti60_2D_Graphics_Accelerator/rtl/common/simple_dual_port_ram.v)：通用伪双口 BRAM 原语推导模块。提供标准单时钟写、单时钟读接口，用于 FIFO 与行缓存的底层实例化。

### 第 6 章：DDR3 控制器硬核接口、防撕裂双缓冲与四重硬件防线

#### 1. 核心功能职责
管理板载 256MB DDR3 物理芯片的初始化、动态时序校准与突发读写；通过硬件锁相机制协调前台扫描缓冲与后台渲染缓冲的原子切换，杜绝画面撕裂。重构后的 `dma_top` 与 `video_write_guard` 构筑了无懈可击的防撕裂与防欠载死锁屏障。

#### 2. 关键信号走线（需重点追踪）
* **物理引脚与校准信号**：
  - `ddr_ck_hi/lo`, `ddr_cke`, `ddr_addr`, `ddr_ba`, `ddr_ras_n`, `ddr_cas_n`, `ddr_we_n`：DDR3 物理命令控制引脚。
  - `ddr_dq_*`, `ddr_dqs_*`, `ddr_dm_*`：双向高速数据与选通引脚。
  - `cal_done`：物理层校准完成标志，拉高前系统处于挂起等待状态。
* **防撕裂双缓冲握手与优先级仲裁**：
  - `vdma_next_base` / `vdma_right_next_base` [27:0]：APB 寄存器下发的待切换左右半屏显存基地址。
  - `vdma_active_base` / `vdma_right_active_base` [27:0]：当前场生效的物理显存读指针。
  - `vdma_vsync_flag`：垂直场消隐单脉冲，驱动固件中断与帧翻页。
  - `video_read_priority`：扫描 FIFO 水位缺水指示（Watermark < 512）。
  - `admit` / `aw_held`：守卫模块门控 AXI 写通道握手信号。

#### 3. 【关键复盘】上板画面撕裂 BUG 根因剖析与四重硬件防线
在系统进行 Triad 架构解耦重构后，上板实测曾偶发严重画面横向撕裂与像素错位。研发团队深入微架构，排查定位了四大根因并部署了四重硬件加固防线：

1. **第一重防线：修复优先级守卫反转（`video_write_guard.v`）**
   - **根因**：原写守卫中将倒计时超时强制开门条件误并入主准入逻辑：`admit = !write_pending && (!video_priority || hold_out || aw_held)`。当 BitBlt 持续高负载大面积写入时，`hold_out` 频繁倒计时归零，强行开门放行大量写事务，导致读扫描 FIFO 水位被抽干，引发扫描欠载断流撕裂；
   - **加固**：果断剔除 `|| hold_out`，恢复为标准协议防线：
     ```verilog
     wire admit = !write_pending && (!video_priority || aw_held);
     ```
     只要 FIFO 缺水（`video_priority` 为高），绝不放行任何新的写握手；仅依靠 `aw_held` 满足 AXI 握手原子性，彻底切断写抢占引起的断流。

2. **第二重防线：齿轮箱欠载相位冻结（`dma_top.v` Gearbox `word_stall`）**
   - **根因**：128-bit 转 32-bit 的四相解包计数器 `sub_pix_cnt` 在 FIFO 暂时读空时仍在 `t_de` 驱动下盲目自增。当后续 DDR 数据回填时，四相索引已经偏离真实字边界，导致整行后续所有像素产生 1~3 像素（1/4 ~ 3/4 字）的永久性水平错位撕裂；
   - **加固**：建立 `word_stall` 欠载侦测：
     ```verilog
     wire word_stall = fifo_rempty && (sub_pix_cnt == 2'd0) && t_de;
     ```
     在 FIFO 读空期间强行冻结 `sub_pix_cnt` 步进，确保数据注入后严格从第 0 相对齐恢复，行像素永不滑移。

3. **第三重防线：CDC 场消隐脉冲 16 周期展宽与边沿对齐（`video_timing_gen.v`）**
   - **根因**：像素时钟域（85.71 MHz，周期 11.66 ns）向 AXI 时钟域（100 MHz，周期 10 ns）传递的 `frame_clear` 原为 1 周期单脉冲，跨时钟域两级同步器存在采样漏捕获概率。一旦漏拍，AXI 读状态机的行地址计数器未能归零，导致前后两帧画面在同一屏幕上下交叠撕裂；
   - **加固**：在时序发生器中强制展宽 `frame_clear` 为 **16 像素时钟周期**（约 186.6 ns）：
     ```verilog
     frame_clear <= (v_cnt == V_ACT) && (h_cnt < 12'd16);
     ```
     并在 `dma_top` 内部通过双级打拍触发器检测上升沿单脉冲（`frame_clear_pulse`），彻底杜绝跨时钟漏帧。

4. **第四重防线：顶层单点原子暗影基地址分发（`dma_fb_reader.v` & `ti60_top.v`）**
   - **根因**：`dma_fb_reader` 内部维护了本地的影子寄存器 `cur_active_base`，与顶层 `active_base` 的翻页时序存在竞态条件，导致某些场扫描读到一半被切换了部分地址；
   - **加固**：删除 `dma_fb_reader` 内部的所有本地影子寄存器，全部显存读基地址统一由系统顶层单点在场消隐安全区间原子打拍下发，全系统读地址步调绝对一致。

### 第 7 章：HDMI/DVI 视频编码与物理差分串化输出

#### 1. 核心功能职责

  - `tmds_data2_o` [9:0]：红色通道编码字。
  - `tmds_clk_o` [9:0]：TMDS 时钟通道字。
  - `tmds_*_TX_OE`, `tmds_*_TX_RST`：易灵思物理差分输出使能与复位信号。

### 第 8 章：游戏固件架构、内存映射与硬件抽象层驱动

#### 1. 核心功能职责

#### 2. 关键信号与软件调用流（需重点追踪）

  - `GPU2D_REG_COLOR_MATRIX`：写入受击或开大招的色彩滤镜控制字。
