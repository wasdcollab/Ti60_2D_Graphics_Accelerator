# 分步实施任务卡（Task Execution Cards）

> **使用说明**：
> 1. 本文档将宏观演进规划切分为 **13 个独立的原子化任务卡**。
> 2. **每一次只下发一个任务**。每个任务卡末尾均附带了【单次下发提示词建议】，主人只需复制该提示词发送给 AI 即可开始当前任务。
> 3. 每个任务完成后，严格按照卡片中的【验收标准】进行验证并生成比特流/固件，确认无误后再进行下一个任务。

# Phase 0：基础设施与空间解绑

## 任务卡 01：固件空间解放：剥离 12.3KB 背景资产至 DDR
* **前置依赖**：无
* **目标与范围**：
  解除当前固件 64,512 字节硬限制（当前已占 64,432 字节，只剩 80 字节）。将常驻片上 RAM 的三大背景 RLE 压缩数据移至 DDR 资产空间，开机由 DDR 映射加载。
* **背景资产账目审查**：
  - `sw/app/stage_bg.c` 中：
    - `rle_stage_dream`: 3,883 字节
    - `rle_stage_lava`: 3,842 字节
    - `rle_stage_ice`: 4,588 字节
    - 合计占用：**12,313 字节（12.02 KB）**！
* **涉及文件**：
  - `tools/build_visual_assets.py`（打包背景 RLE 压缩包至 DDR 预设地址）
  - `sw/driver/memory_map.h`（增加背景 RLE 的 DDR 地址宏定义）
  - `sw/app/stage_bg.c`（修改指针指向 DDR 地址，移除静态 C 数组）
  - `sw/build_firmware.py`（验证固件体积缩减与可用余量）
* **【有争议 / 暂缓待定项说明】片上 BRAM 硬件级扩容**：
  - 若未来极端业务确实需要 >64KB 纯机器指令，需启动 Efinity IP Manager 将 SoC 片上 RAM 扩容至 128KB（2的幂次）；当前因剥离方案已可提供 12.3KB 充裕空间，且不承担重新生成 SoC IP 的风险，硬件扩容暂行挂起待定。
* **验收标准**：
  - 固件编译报告显示占用从 **64,432 字节**（`sw/build/firmware.sym` 的 `image_end` = 0xF900FBB0，
    距上限仅 80 字节）降至 **约 51,900 ~ 52,100 字节**，**片上可用余量增至约 12.2 ~ 12.4 KB**；
    实测口径：三关底板 `rle_stage_*` = 3,883 + 3,842 + 4,588 = **12,313 B**，
    加三个 64 B 调色板 = **12,505 B**，全部剥离后才能拿到这个余量；
  - 三个关卡的背景在真机上渲染完全正常，色彩和切换无任何异样；
  - 零 Verilog 变动，完全兼容现有比特流。
* **【单次下发提示词建议】**：
  > “请执行【任务卡 01：固件空间解放：剥离 12.3KB 背景资产至 DDR】。请将 stage_bg.c 中的三大背景 RLE 数据剥离并由 DDR 映射加载，释放 12KB 片上空间，编译固件并验证背景解压与关卡切换完全正常。”

## 任务卡 02：RISC-V 硬件乘除法（RV32IM）编译使能
* **前置依赖**：任务卡 01 完成
* **目标与范围**：
  消除 GCC 编译生成的 `__mulsi3` 和 `__divsi3`（软件模拟乘除法循环），直接使能 SoC 硬件现存的单周期乘法器与硬件除法器，将游戏代数与弹幕运算提速 40 倍。
* **硬件现状确认**：
  - `ip/soc/soc.v` 审查证实：硬件 VexRiscv 内部已例化 `MulPlugin`（消耗 4 个 DSP48）和 `MulDivIterativePlugin`（硬件除法器），位流中乘法核早就存在；
  - 但 `ip/soc/settings.json` 里写的却是 `"MULDIV_EXT": "1'b0"` / `"BARREL_SHIFTER": "1'b0"`
    —— **参数与网表矛盾**（证据与推演见《未调用资源使用指南.md》§1.3 的
    2026-09-25 补充）。所以本卡**不是"改一个编译选项"就能收工的**：
    必须先验硬件是否真的**译码** `mul` / `div`。
  - **验证路径（必须实测，不接受推断）**：反汇编现有固件确认 `__mulsi3` 仍被调用
    → 用 `-march=rv32im` 编一版 → 在 `sw/build/firmware.map` 确认
    `muldi3.o` / `div.o` 消失 → **上板跑一遍**（游戏可运行、分数与速度正确）→ 才允许合并。
    若硬件不译码 M 扩展，非法指令会**当场异常**（不是"悄悄算错"），风险外显。
* **涉及文件**：
  - `sw/build_firmware.py`（编译标志由 `-march=rv32i` 更新为 `-march=rv32im`）
* **实现指导**：
  1. 修改 `sw/build_firmware.py` 中的 `CFLAGS`，将 `-march=rv32i` 改为 `-march=rv32im`；
  2. 运行 `sw\build_firmware.bat`，检查 `sw/build/firmware.map`；
  3. 确认 `muldi3.o` 和 `div.o` 彻底消失，乘法操作全部变为原生硬件 `mul` / `div` 指令。
* **验收标准**：
  - 固件二进制不再链接 `libgcc.a(muldi3.o)`；
  - 固件体积进一步缩小（软件乘除法模拟函数被抹除）；
  - 板卡烧录验证游戏运行正常，所有速度与分数计算精准无误。
* **【单次下发提示词建议】**：
  > “请执行【任务卡 02：RISC-V 硬件乘除法使能】。请更新 sw/build_firmware.py 编译选项为 -march=rv32im，直接调用现存的硬件乘除法核，消除软件循环，编译并验证固件正常运行。”

## 任务卡 04：【方案 A】BitBlt 硬件加法混合器开发（`OP_ADD`）
* **前置依赖**：任务卡 01 完成
* **目标与范围**：
  在 BitBlt 2D 绘图引擎中增加 **硬件饱和加法混合通道（`OP_ADD` = 3）**，用于大玉、激光、符卡弹与高光粒子的物理级光线叠加。
  **同时完整保留原有的 `OP_ALPHA`（操作类型 2）**，保留其作为半透明黑色黑屏渐隐（Fade）、UI 半透明对话框、BOSS 暗色半透明气场护盾的专职能力。
* **数学原理**：
  $$Out_{RGB} = \min(255, Dst_{RGB} + Src_{RGB})$$
  - 黑色底色（0, 0, 0）天然透光（$Dst + 0 = Dst$），无需 ColorKey；
  - 重叠区域光芒相加，超过 255 自动饱和为纯白光心，符合真实光学规律。
* **涉及文件**：
  - `rtl/bitblt/bitblt_alpha_blend.v`（增加加法混合数据通路，复用读回的 Dst 数据）
  - `rtl/bitblt/bitblt_top.v`（译码 `OP_ADD` 操作类型）
  - `sw/driver/gpu2d.h` / `sw/driver/gpu2d.c`（增加 `GPU2D_OP_ADD = 3` 及 `gpu2d_add()` API）
* **验收标准**：
  - BitBlt 引擎能正确执行 `OP_ADD` 混合；
  - 黑底高光素材贴在彩色背景上呈现半透明叠加，多层重叠处呈现白心高光；
  - 现有 `OP_ALPHA`、`OP_COPY`、`OP_FILL` 功能 100% 保持正常。
* **【单次下发提示词建议】**：
  > “请执行【任务卡 04：【方案 A】BitBlt 硬件加法混合器开发】。请在 BitBlt 引擎中添加 OP_ADD 饱和加法混合支持，同时保留原有 OP_ALPHA，更新底层驱动并在主程序中验证加法高光绘制。”

## 任务卡 05：【方案 B】视频扫描端 SRL8 硬件 Bloom 外发光滤镜开发
* **前置依赖**：任务卡 01 完成
* **目标与范围**：
  利用 FPGA 闲置的 **13,993 个 SRL8 移位寄存器**，在 HDMI 视频扫描输出端开发纯硬件级 **Bloom 高光外发光滤镜**。
  海量普通小弹在 DDR 中仅需单向最高速 Copy，视频输出端在送显途中实时向外扩散出柔和光晕，**完全免除 DDR 读写开销，稳锁 75 FPS**。
* **涉及文件**：
  - `rtl/v_dma/video_bloom_filter.v`（新建硬件模块，利用 SRL8 构筑 3 行行缓冲 + 高斯扩散算子）
  - `rtl/v_dma/video_dma_read.v`（接入视频输出通路）
  - `rtl/bitblt/bitblt_apb_regs.v`（增加 Bloom 发光阈值与发光强度控制寄存器）
  - `sw/driver/gpu2d.h`（增加驱动 API）
* **实现指导**：
  1. 利用 Titanium 的 `EFX_SRL8` 或移位寄存器推断，缓存 3 行像素数据（每行 1024 像素）；
  2. 提取亮度高于阈值（例如 $Y > 200$）的高光像素，进行 $3\times 3$ 均值/高斯核模糊；
  3. 将模糊后的辉光以硬件饱和加法叠加回主画面；
  4. APB 寄存器可实时调节发光阈值与开关。
* **验收标准**：
  - 综合报告显示有效调用上千个 SRL8，不破坏 85.7 MHz 时序；
  - 屏幕上的普通单色子弹边缘自然散发发光光晕；
  - DDR 监控指标显示没有产生任何额外 DDR 访问流量。
* **【单次下发提示词建议】**：
  > “请执行【任务卡 05：【方案 B】视频扫描端 SRL8 硬件 Bloom 滤镜开发】。请利用闲置 SRL8 编写 3 行行缓冲高光外发光模块并接入视频流，提供 APB 阈值调节，编译生成比特流并验证发光效果。”
